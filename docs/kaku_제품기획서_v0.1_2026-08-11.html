かく(Kaku) — 쓰면서 외우는 JLPT 단어장

작성일 2026-08-11 · 작성자 【이름】 · 상태: 초안 (배포 전)

1. 한 줄 정의

일본어 단어를 눈으로 회독하는 게 아니라, 직접 타이핑해서 인출(retrieval)하며 외우는 JLPT 단어·한자 학습 앱. 웹과 모바일(PWA)에서 가입·설치 장벽 없이 즉시 사용한다.

2. 문제 정의 — 왜 만드는가

기존 단어 앱(플래시카드·4지선다)의 학습 흐름은 대부분 "보고 → 아는 것 같으면 넘기기"다. 이 방식의 문제는 인지과학에서 오래 지적되어 온 것으로, 재인(보면 앎)과 인출(스스로 떠올림)은 다른 능력이라는 점이다. 보기에서 고르는 훈련만 하면 시험지 앞에서, 회화 중에 단어가 떠오르지 않는다.

  • 플래시카드 앱: 회독 속도는 빠르나 "아는 것 같은 착각(illusion of knowing)"을 만든다.
  • 4지선다 앱: 재인만 훈련한다. JLPT 문자·어휘 파트의 핵심인 한자 → 읽기 인출과 거리가 있다.
  • Anki류 SRS 앱: 강력하지만 덱 구성·설정의 진입 장벽이 높아 비개발자 학습자가 이탈한다.
핵심 가설(H1): 단어를 보고 읽는 법을 직접 타이핑해서 인출하는 방식은 4지선다 재인 방식보다 단어 정착률(장기 기억 도달률)이 높다. — 앱에 두 방식이 모두 있으므로 자체 데이터로 검증 가능하다.
본인이 일본어 공부하면서 겪은 "외운 줄 알았는데 안 떠오르던" 경험을 2~3문장으로 추가하면 설득력이 크게 올라갑니다.

3. 타깃 사용자

주 타깃 — JLPT를 준비하는 직장인·취업준비생

항목내용
상황N3~N2(일부 N1) 준비. 시험 날짜가 있어 동기가 명확함
시간하루 20~30분. 출퇴근·점심·자기 전 자투리 시간, 주로 폰
페인포인트단어책은 안 들고 다니게 됨 · 앱은 눈으로만 넘겨서 남는 게 없음 · Anki는 세팅이 귀찮음
니즈열면 바로 "오늘 할 것"이 정해져 있고, 자투리 시간에 한 세션이 끝나는 학습
주변의 실제 JLPT 준비생 1~2명을 인터뷰해서 "페인포인트" 줄을 실제 발화로 교체해 보세요. (예: "○○님: 단어장 앱 3개 깔았는데 다 3일 쓰고 지웠어요")

4. 경쟁 분석 & 포지셔닝

제품강점한계
AnkiSRS의 표준, 무한 커스텀덱 만들기·설정 장벽. 학습 방식 설계를 사용자에게 떠넘김
JLPT 단어장 앱류레벨별 단어 정리 잘 됨회독 + 4지선다 중심 = 재인 훈련. 수동적 학습
Duolingo습관화(streak) 설계 최고JLPT 어휘 커버리지 부족, 시험 대비용 아님
かくJLPT 전 레벨 어휘(8,110단어)·한자(2,212자) + 타이핑 인출 + 제로 셋업(가입 없음, 열면 바로)

포지셔닝 한 문장: "Anki의 과학 × Duolingo의 간편함 × JLPT 전용"

5. 핵심 가치 (차별점 3가지)

  1. 타이핑 인출 연습 — 단어(한자)를 보고 읽는 법을 로마자로 직접 입력 → 실시간 히라가나 변환. JLPT 문자·어휘 파트와 같은 인지 과정.
  2. 알아서 도는 복습 시스템 — SRS(라이트너 5상자) + 오답 노트 자동 수집·자동 졸업. 사용자는 설정할 게 없다.
  3. 제로 프릭션 — 가입·로그인·설치 없음. URL 하나로 시작, 데이터는 기기에 저장. (PWA로 홈 화면 설치 지원)

6. 핵심 루프 — 매일 열게 만드는 구조

앱 열기홈 화면 아이콘
→
오늘의 복습 확인Phase 2 · SRS 만기 요약
→
세션 학습타이핑 인출 · 20~30문항
→
오답 노트틀린 것만 재도전
→
streak 갱신Phase 2 · 연속 학습일

현재(v0.1)는 "열면 공부할 수 있는" 앱이다. 이 루프의 굵은 두 칸(오늘의 복습, streak)이 "매일 열게 되는" 앱으로 바꾸는 핵심이며, Phase 2의 최우선 과제다.

7. 성공 지표

⭐ North Star — 주간 정착 단어 수 한 주에 상자4(익힘)에 도달한 단어 수. "공부한 척"이 아니라 "실제로 외워진 양"을 측정
D7 리텐션 첫 방문 후 7일 안에 다시 온 사용자 비율. 습관 루프 검증의 핵심
세션 완료율 시작한 세션을 끝까지 마친 비율. 세션 길이·난이도 설계 검증
오답 노트 졸업률 노트에 들어온 단어가 상자4로 졸업하는 비율. 복습 루프의 실효성

수집 방법

  • 학습 기록(상자·정오답): 앱 내 localStorage에 저장 → 앱 내 통계 화면으로 시각화 (기기 밖으로 나가지 않음)
  • 행동 지표: GoatCounter(무료·익명) 이벤트 수집 — 가입·개인정보 없이 아래 이벤트만 전송

수집 이벤트 설계 (v0.1 구현·가동 중)

이벤트발생 시점답하는 질문
visit앱 실행사용량, 리텐션(근사), 시간대 패턴

모든 이벤트에 학습 목적 × 목표 레벨 × 시험일 유무 세그먼트가 경로로 붙는다 (예: /word_settled/job-N2-exam) — "취업 준비 N2 수험생"의 정착률을 따로 볼 수 있다. 온보딩 맛보기 세션은 학습 이벤트를 기록하지 않는다.

8. 검증 계획 — 가설과 실험

가설확인 방법판단 기준(초안)
H1 타이핑 > 고르기같은 사용자의 타이핑 모드 vs 고르기 모드 단어의 상자4 도달 속도 비교타이핑 학습 단어의 정착 속도가 유의미하게 빠르면 채택
H2 오답 노트가 정착률을 올린다오답 노트 사용자/미사용자(또는 사용 전후)의 졸업률 비교졸업률 차이 확인
H3 자투리 시간 = 모바일애널리틱스의 기기·시간대 분포모바일 비중 > 60%면 모바일 UX에 계속 투자
지인 테스터 5~10명을 모을 계획(누구에게, 어떻게 부탁할지)을 여기에 한 줄로 적어두세요. 검증 계획은 "누가 써주는가"까지 있어야 완성입니다.

Phase 3 · 확장
기록 내보내기/기기 간 이동 → 계정·동기화 검토, 예문·청해, 스토어(네이티브 앱) 출시 검토

10. 리스크와 한계 (알고 시작하는 것)

  • 콘텐츠 정확성 — 한국어 뜻은 자체 번역. 사용자 신고 기능 또는 검수 사이클 필요.
  • 모바일 타이핑 피로도 — 폰에서 로마자 입력이 데스크톱보다 느림. 세션 길이 기본값을 모바일에선 짧게 가져가는 실험 필요.
  • 로컬 저장의 한계 — 기기를 바꾸면 기록이 사라짐. Phase 3의 동기화 전까지는 내보내기 기능으로 보완.
  • 1인 개발 리소스 — 범위를 지표가 증명하는 것에만 집중. "만들고 싶은 것"보다 "지표가 필요하다고 말하는 것".
